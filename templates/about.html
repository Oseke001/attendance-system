Attendance System

A digital classroom attendance management system designed to make attendance faster, more organized, and more reliable.

The system combines user accounts, class management, temporary attendance codes, optional location verification, and digital attendance records.

About the Project

The Attendance System is a web-based application developed to provide a digital alternative to traditional paper-based classroom attendance.

The Problem

Traditional classroom attendance can be time-consuming and difficult to manage. Paper attendance sheets can become disorganized, records can be difficult to search, and students may sometimes sign attendance for other students.

The Solution

This system provides a digital way to manage classroom attendance. Students join their classes using a unique class code and submit attendance using a temporary attendance code generated for an active session.

When location verification is enabled, the system also checks whether the student's device is within the permitted distance from the classroom location.

Main Features

How It Works

The system follows a simple workflow involving registration, class membership, attendance sessions, verification and digital record keeping.

Step 1 — Create an Account

A user creates an account using their name, matriculation number, email address and password. The matriculation number is unique and helps identify the student.

Step 2 — Create or Join a Class

An authenticated user can create a class. The person who creates the class automatically becomes the Owner.

Other users can join an existing class using its unique class code and become Members.

Step 3 — Class Roles

Roles are specific to each class. A user can therefore have different roles in different classes.

  • Owner: Manages the class and has the highest level of class-specific control.
  • Admin: Assists with permitted class tasks and can perform manual attendance.
  • Member: Joins the class and submits attendance.

Step 4 — Start Attendance

The class Owner starts an attendance session. The system generates a temporary six-character attendance code.

The attendance session has an expiry time. Location verification can also be enabled for the session.

Step 5 — Student Submits Attendance

A student opens the class and enters the active attendance code.

The system checks that:

  • The student is logged in.
  • The student belongs to the class.
  • An active attendance session exists.
  • The attendance session has not expired.
  • The submitted code is correct.
  • The student has not already attended the session.

Step 6 — Location Verification

If location verification is enabled, the system obtains the student's device location and calculates the distance between the student's location and the configured classroom location.

If the student is within the permitted radius, attendance can be approved. If the student is outside the permitted radius, the attendance submission is rejected.

Step 7 — Attendance Record

When all required checks pass, the system creates an attendance record containing information such as the student, class, attendance session, timestamp, status and location information when applicable.

Step 8 — Confirmation

The student receives a confirmation message after a successful submission and is returned to the class page.

What Happens When Attendance Fails?

The system does not create an attendance record when an attendance submission fails.

Examples of failure include:

  • Incorrect attendance code
  • Expired attendance session
  • No active attendance session
  • Duplicate attendance submission
  • Location permission denied when required
  • Student outside the permitted classroom radius
  • User is not a member of the class

Frequently Asked Questions

What is the Attendance System?

It is a web-based platform for managing classroom attendance digitally using class membership, temporary attendance codes and optional location verification.

How do I join a class?

Log into your account and use the unique class code provided by the class Owner.

Who can create a class?

Any authenticated user can create a class. The user who creates the class automatically becomes the Owner.

Can a user belong to multiple classes?

Yes. A user can belong to multiple classes and can have a different role in each class.

How long does an attendance code remain valid?

The attendance session has a configured expiry time. Once the session expires, students can no longer use that session to submit attendance.

Why does the system request my location?

Location is used when location verification is enabled. It allows the system to determine whether the student is within the permitted distance from the classroom.

What happens if I deny location permission?

If location verification is required for the session, the system cannot approve attendance without the required location information.

Can I submit attendance more than once?

No. The system checks for an existing attendance record for the student and the current session before creating a new record.

What happens if I enter the wrong code?

The submission is rejected and the system displays an appropriate error message. An attendance record is not created.

What happens if I am outside the classroom?

If location verification is enabled and your device is outside the permitted classroom radius, the attendance submission is rejected.

Can attendance be recorded manually?

Yes. Authorized Owner/Admin users can manually record attendance for students who are unable to complete the normal attendance process.

Can an Admin view past attendance history?

No. In the current system design, Admin access to past attendance history is restricted. The Owner has access to the relevant attendance history.

What happens when an attendance session ends?

The session is no longer active and students cannot use its attendance code to submit attendance.

Is location verification always required?

No. Location verification is enabled by default for an attendance session but can be disabled when appropriate.

How does the system prevent duplicate attendance?

Before creating a new attendance record, the system checks whether the student already has a record for the current attendance session.

Where is the application hosted?

The application is deployed online using Render, with PostgreSQL used as the production database.
